# Gestión de las Partes Interesadas

1. Gestión de las partes interesadas: A partir de la lista de interesados identificada previamente, indicar para cada uno:

2. Qué debe cumplir el proyecto con esa parte interesada: necesidades, expectativas, compromisos o condiciones que el proyecto debe satisfacer respecto de ese interesado.

3. Nivel de influencia: Alto, Medio o Bajo, según la capacidad que tenga el interesado de afectar decisiones, alcance, desarrollo o aceptación del proyecto.

## Ejemplo:

| Parte interesada                         | ¿Qué debe cumplir el proyecto con esta parte interesada?                                                                                 | Nivel de influencia |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| Cliente / Responsable de la organización | Entregar las funcionalidades acordadas, respetar el alcance aprobado y permitir la validación de los principales avances.                | Alto                |
| Usuario final                            | Proporcionar una solución que permita realizar las tareas definidas de forma clara y que contemple los requisitos relevados para su uso. | Medio               |
| Equipo de desarrollo                     | Contar con requisitos claros, tareas organizadas, acceso a las herramientas necesarias y criterios definidos para las entregas.          | Alto                |
| Docente responsable                      | Cumplir con las consignas, entregables, documentación y fechas establecidas para el proyecto académico.                                  | Alto                |
| Especialista del dominio                 | Contemplar y validar correctamente las reglas específicas del dominio que sean necesarias para el funcionamiento del sistema.            | Medio               |

Importante: en la columna “¿Qué debe cumplir el proyecto con esta parte interesada?” se deberá indicar qué espera, necesita o requiere esa parte interesada del proyecto y qué deberá cumplir el equipo para satisfacerlo. No se busca indicar solamente cómo se comunicarán con ella.

Por ejemplo, “hacer una reunión cada 15 días con el cliente” no sería lo que buscamos en esta columna. Eso corresponde a Comunicaciones. En cambio, “entregar las funcionalidades acordadas y permitir que el cliente valide los avances” sí representa qué debe cumplir el proyecto con ese interesado.
